## 发现的两个设计问题

1. **Task 模型没有 userId 字段** —— `currentValue` / `status` 是全局的，多个用户会共享同一份任务进度。真实活动里任务进度必须按用户隔离。建议 Task 加 userId，或把进度拆到 UserState 里。
2. **`prize.rate`（'99.99%'）是纯展示字段**，不参与实际抽奖概率计算；真实概率由 `prob` 权重决定。改概率要改 `prob`，改 `rate` 只影响界面文案。

## 2026-09-07 11:40 — 修复移动端弹窗尺寸溢出（turkish-wheel）

### 现象

抽奖奖励弹窗严重溢出：金边框约 2 倍大小，CONGRATULATIONS 等内容被截断。

### 排查过程

1. 构建产物 CSS：`750px → 7.5rem`、`154px → 1.54rem` 全部转换正确 → **pxtorem 本身生效**
2. Vant 的 index CSS 里 344 个 rem、仅 8 个 px → **Vant 也转了**
3. 唯一没转的：`SectionBorder` 组件用 `:style="{ width: (width??750) + 'px' }"` 拼的 inline style

### 根因（结论）

1. **postcss-pxtorem 只处理 CSS 文本，碰不到 JS 运行时的 inline style。**
   SectionBorder 的全部尺寸都是 props 拼的 inline style，所以金边框一直按物理像素渲染
   （726px 而非 7.26rem），在 375 屏幕上放大 2 倍 → 正是截图里的溢出。
2. **Vant 的 rootValue 37.5 是错的，应为 50。**
   推导：运行时 `rem = 视口宽 / 7.5`，要求 `rootValue × 7.5 = 设计稿宽度`。
   业务 750 设计稿 → 100；Vant 375 设计稿 → 50。用 37.5 会让 Vant 全部放大 1.33 倍。
   hoby 里的 37.5 是给 antd-mobile 的死配置（它根本没装 antd-mobile），所以从没暴露。

### 修复

- 新增 `apps/web/src/utils/rem.ts` 的 `designPx()`，inline 尺寸统一走它
- `SectionBorder` 7 处 inline px 全改 designPx()（4 个弹窗组件共用，一处修好全好）
- `vite.config.ts` 里 uiLibPxtorem rootValue 37.5 → 50
- 新增 `rem.test.ts` 3 个用例锁定约定

### 验证

- web test 5/5 ✓
- 产物 JS：`function A(e){return \`${e/k}rem\`}` 即 designPx；无残留 inline px ✓
- 产物 CSS：Vant `.van-dialog` 默认宽 320px → `6.4rem`（按 50 换算）✓

### 经验（写代码要记住）

**凡是 `:style` 里拼尺寸，一律用 designPx()。写 px 就等于物理像素，postcss 救不了。**

## 2026-09-07 18:16 — 修复 rank.vue 运行时报错 `$setup.numberThumbnail is not a function`

### 根因

`rank.vue`（template-activity/sections）里 `const { numberThumbnail } = utils`（line 201），但
`src/utils/index.ts` 的 utils 对象当初只补了 to/cfShowToast/formatNumber/transformLocales，
漏了 `numberThumbnail` → 编译通过、运行时 `rank.vue:82/118/171` 调用即炸。

### 修复

从 hoby 项目 `activity/src/utils/utils.js` 移植 `numberThumbnail` + `numberThumbnail2`，并补一个
精确的 `divide`（移植自 `cal.js`，避免浮点误差）。积分接口放大十倍，numberThumbnail 先 /10 再按
K/M 缩略；numberThumbnail2 不放大（目前 monorepo 没用到，但保持与原项目一致）。

### 验证

- `pnpm --filter @mono/web build` ✓（exit 0，ganesh-chaturthi chunk 123.97 kB JS / 25.32 kB CSS）
- node 抽验输出：12340→1.2K、12340000→1.2M、9999999999→999.9M+ ✓

### 经验

模板活动依赖的 utils 方法要全量对齐，不能只补用到的几个；缺方法会在运行时才暴露，
build 不报错。下次从 copy/ 迁移活动，先把 utils 依赖清单列全再动手。
